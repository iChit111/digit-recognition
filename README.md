# 🥷 Neural Ninjas — Handwritten Character Recognition (EMNIST ByClass)

A deep learning + data analytics project that recognises handwritten **characters** —
digits `0–9`, uppercase `A–Z` and lowercase `a–z`, **62 classes in all** — using the
**EMNIST ByClass** dataset, TensorFlow/Keras and scikit-learn.

Built by **Team Neural Ninjas** as a group project at **PCCOE Pune**.

> **Note:** this project started on MNIST (10 digit classes) and was migrated to
> EMNIST ByClass (62 character classes). The source files keep their original
> names and structure so the migration reads as a clean diff; the headers inside
> each file record what changed and why.

---

## 📌 What This Project Does

The repo has **two tracks** that share the same dataset and the same label mapping:

**Track A — Neural network pipeline (full dataset)**
- Loads all 814,255 EMNIST ByClass images (697,932 train / 116,323 test)
- Trains a dense neural network over 62 classes, with class weights for imbalance
- Evaluates it: per-group accuracy, a 62×62 confusion matrix, confused pairs,
  case-only error analysis, misclassified examples
- Runs an interactive demo that predicts a character and shows a confidence chart

**Track B — DEV mini project, Phases 1–5 (50,000-image sample)**
- Phase 1: loads the data into a CSV and summarises it
- Phase 2: cleaning, type conversion, 10 engineered shape features, encoding, scaling
- Phase 3: exploratory data analysis — 10 figures
- Phase 4: correlation, multicollinearity, ANOVA / t-tests, feature importance, selection
- Phase 5: five classifiers trained and compared on identical inputs

## 🚀 Track A — Neural Network Pipeline

### Step 1 — Load and explore the data
```bash
python src/data_loader.py
```
- Downloads EMNIST ByClass (first run only) and corrects its known orientation
  quirk (the raw images are rotated 90° anti-clockwise and mirrored)
- Saves a 5×5 grid of sample characters to `sample_images.png`
- Saves a 62-class distribution chart to `label_distribution.png`
- Normalises pixels to `[0, 1]` and flattens each image to 784 values
- Computes class weights, since ByClass is heavily imbalanced

### Step 2 — Train the model
```bash
python src/model.py
```
- Builds the dense network (784 → 512 → 256 → 62)
- Shuffled, seeded, **stratified** 90/10 train/validation split
- Trains with class weights and EarlyStopping (max 100 epochs, patience 5,
  best weights restored)
- Saves loss/accuracy curves to `results/training_history.png`
- Saves the model to `results/model.h5`

### Step 3 — Evaluate the model
```bash
python src/evaluate.py
```
Reports, on the 116,323-image official test split:
1. Overall accuracy and loss
2. Per-group accuracy — digits, uppercase, lowercase
3. A row-normalised 62×62 confusion matrix → `results/confusion_matrix.png`
4. The top 15 confused `true → predicted` pairs
5. How many errors are **case-only** (e.g. `c` predicted as `C`)
6. 15 misclassified images → `results/misclassified_examples.png`

### Step 4 — Run the demo
```bash
python src/demo.py                      # random test character
python src/demo.py --index 42           # test image #42 (0–116322)
python src/demo.py --index 99 --count 5 # 5 images starting at #99
python src/demo.py --random --count 5   # 5 random predictions
python src/demo.py --model path/to.h5   # use a different saved model
```
Shows the character next to a confidence bar chart over all 62 classes and
saves each prediction to `results/demo_prediction_*.png`.

### Model architecture

```
Input          →  784 units   (flattened 28×28 image)
Hidden Layer 1 →  512 units   (ReLU)  →  Dropout 0.3
Hidden Layer 2 →  256 units   (ReLU)  →  Dropout 0.2
Output         →   62 units   (Softmax — one probability per character)
```

| Setting          | Value                                          |
|------------------|------------------------------------------------|
| Optimizer        | Adam                                           |
| Loss             | Sparse Categorical Crossentropy                |
| Epochs           | up to 100, EarlyStopping (patience 5)          |
| Batch size       | 128                                            |
| Validation split | 10%, stratified, seeded (`SEED = 42`)          |
| Class weights    | enabled (`USE_CLASS_WEIGHTS = True`)           |
| Total parameters | 503,102                                        |

Settings live at the top of `src/model.py` — change them there, not inside the
functions.

## 📊 Track B — DEV Mini Project (Phases 1–5)

Run the phases **in order**; each one consumes the previous one's output.

### Phase 1 — Data loading & summary
```bash
python src/phase1_data_summary.py            # reuses the CSV if it exists
python src/phase1_data_summary.py --rebuild   # re-creates it
```
EMNIST ships as arrays, and 697,932 × 784 is far too large for pandas-based EDA
and for SVM/KNN. So Phase 1 takes a **stratified** 50,000-image sample (every
class keeps its real share) and writes `data/emnist_byclass_sample.csv`
(~97 MB): columns `label`, `char`, `pixel0 … pixel783`. It then reports shape,
columns, dtypes, missing values and `describe()`.

### Phase 2 — Preprocessing & transformation (ETL)
```bash
python src/phase2_preprocessing.py
```
Missing values → blank-image removal → duplicate removal (exact and
conflicting-label) → type conversion → **10 engineered shape features** →
label/one-hot encoding → normalisation and standardisation.

The 10 features: `ink_pixel_count`, `mean_intensity`, `bbox_width`,
`bbox_height`, `aspect_ratio`, `ink_density`, `centroid_x`, `centroid_y`,
`lr_symmetry`, `tb_symmetry` — illustrated in
`results/phase2_features_explained.png`.

Output: `data/emnist_processed.csv`. It is saved **unscaled** on purpose:
`StandardScaler` learns its mean and standard deviation from the data, so
fitting it across all 50,000 rows would leak test information into Phase 5.
Phase 5 fits the scaler on its training split only.

### Phase 3 — Exploratory data analysis
```bash
python src/phase3_eda.py
```
Ten figures, every one on a shared colour scheme (digits / uppercase /
lowercase), saved as `results/phase3_01…10_*.png`: target distribution,
feature distributions, outlier box plots and example outlier images, features
vs. group and vs. character, look-alike scatter plots, a pair plot, the mean
image per class, and ink-frequency heatmaps.

### Phase 4 — Feature engineering & statistics
```bash
python src/phase4_feature_analysis.py
```
Correlation heatmap, multicollinearity (`|r| > 0.8` pairs plus VIF), ANOVA
across the 62 classes with η² effect sizes, t-tests with Cohen's d, Random
Forest Gini + permutation importance, feature selection over both shape
features and pixels, and interaction features kept only if they lift
cross-validated accuracy by at least 1 pp.

Everything runs on the **80% training split only** — the same split Phase 5
uses — so feature selection cannot leak test information.

Result (`data/selected_features.json`): **7 of 10** shape features kept
(`bbox_width`, `bbox_height` and `mean_intensity` dropped) and **687 of 784**
pixels kept — 694 input columns. Interactions helped Logistic Regression but
not Random Forest. Figures: `results/phase4_01…04_*.png`.

### Phase 5 — Machine learning models
```bash
python src/phase5_models.py        # ~10 minutes
```
Five classifiers on identical inputs, same stratified 40,000 / 10,000 split,
default hyperparameters, no class weights for anyone, and all scaling/PCA
inside a scikit-learn `Pipeline` so it is fitted on the training split only:

| Model                | Accuracy | Macro F1 | Weighted F1 | Digits | Upper | Lower | Fit (s) | Predict (s) |
|----------------------|---------:|---------:|------------:|-------:|------:|------:|--------:|------------:|
| **SVM (RBF)**        | **80.90%** | 63.16% | 78.36% | 93.7% | 73.9% | 62.1% | 36.1 | 47.4 |
| **Dense Neural Net** | 80.36%  | **65.46%** | **78.89%** | 92.9% | 71.1% | 64.6% | 39.3 | 0.7 |
| Random Forest        | 77.34%  | 56.69% | 74.51% | 92.3% | 65.1% | 60.0% | 11.6 | 0.5 |
| KNN (k = 5)          | 76.38%  | 58.05% | 74.55% | 90.6% | 64.9% | 59.8% | 0.4 | 0.5 |
| Logistic Regression  | 71.56%  | 54.64% | 70.44% | 85.6% | 58.9% | 56.6% | 50.8 | 0.1 |

SVM and KNN run on 50 PCA components of the pixels (87.1% of pixel variance).

**Findings**
- SVM (RBF) and the dense network are **statistically tied** — 0.5 pp apart,
  McNemar's test `p = 0.071`. The network has the better macro F1, i.e. it
  handles rare classes better.
- Logistic Regression is weakest: a linear model can't capture curved stroke
  shapes, even with interaction features.
- Digits are recognised far better than letters in **every** model.
- Errors concentrate on characters that are *drawn* identically:
  `l → 1` (199×), `O → 0` (161×), `I → 1` (98×), `0 → O`, `5 ↔ S`.
- **Case-only** confusions (`m/M`, `c/C`, `u/U`, `f/F`, `p/P`, `v/V`) make up
  13–22% of all errors. Lowercase look-alikes are almost never predicted,
  because their uppercase twin is more common in training — the class
  imbalance first seen in Phases 1 and 3.

Outputs: `results/phase5_model_comparison.csv`, `results/phase5_run_log.txt`,
and `results/phase5_01…03_*.png`.

Phase 5 **retrains** the network rather than scoring `results/model.h5`:
`model.h5` was trained on the full EMNIST training split, which contains every
image in the 50,000 sample — including this phase's test rows. Scoring it here
would be testing on images it has already seen.

## 🔍 Notes on the Data

- **Orientation.** EMNIST images ship rotated 90° anti-clockwise and mirrored.
  `data_loader._fix_emnist_orientation()` corrects this, so humans and the
  model see the characters the right way round.
- **Label order.** ByClass uses NIST's official mapping: `0–9` → digits,
  `10–35` → `A–Z`, `36–61` → `a–z`. It lives in `src/label_map.py` and every
  other file imports from there — never hardcode `62` or re-derive the order.
- **No MNIST merge.** MNIST and EMNIST ByClass are both resampled from NIST
  Special Database 19, so merging them adds near-duplicate samples and risks
  train/test leakage rather than new handwriting. ByClass already has ~344,000
  digit samples.
- **Imbalance.** Class counts range from a few thousand to tens of thousands.
  Track A handles it with class weights; Track B reports macro metrics
  alongside weighted ones so rare classes stay visible.
